## 一、端口与扫描方法

**端口**：一个端口就是一个**潜在的通信信道**，也就是**入侵通道**。在客户/服务器结构中，服务器上运行守护进程在端口上监听，客户请求到达就启动服务进程通信；为简化这一过程，每个应用服务程序（WWW、FTP、Telnet 等）被赋予一个唯一的地址，这个地址称为端口。

- 端口号 **16 位**，范围 **0–65535**。
- **公认端口（Well Known Ports）0–1023**：紧密绑定于一些服务，通讯明确表明某种服务的协议，例如 **80 端口实际上总是 HTTP 通讯**。

**什么时候扫**：确定目标主机可达之后。**怎么扫**：向目标端口发送探测数据包，**根据收到的响应判断端口状态**。三种方法：TCP 扫描、FTP 代理扫描、UDP 扫描。

**核心心法**：所有端口扫描都是在问同一件事——**这个端口回了什么**。记住“回什么”，六种方法就不会混。

## 二、六种扫描的判据

| 方法 | 发什么 | 端口开放 | 端口关闭 |
|---|---|---|---|
| TCP Connect | 调 `connect()` 正常建连 | 建连成功，返回 0 | 失败，返回 SOCKET_ERROR |
| TCP SYN | 只发 SYN（半开） | 回 SYN + ACK | 回 RST |
| TCP FIN | 发 FIN | **无任何响应** | 回 RST |
| Xmas | 六个标志位全置 1 | 同 FIN | 回 RST |
| Null | 六个标志位全置 0 | 同 FIN | 回 RST |
| FTP 代理 | 用 PORT 命令指定端口 P | 数据连接建立成功 | 数据连接失败 |
| UDP | 发 UDP 包 | **无响应** | 回 ICMP_PORT_UNREACH |

三个要点：

- **Connect 是唯一“真建连”的**，走完三次握手，所以最准也最不隐蔽。
- **SYN 是半开**：不回最后一个 ACK，连接没建成，所以服务端不记录、日志里没有。
- **FIN / Xmas / Null 是反着的**：**不回应 = 开放**。依据是 RFC 793——关闭端口收到这些包要回 RST，开放端口的监听进程不理会。

**Xmas**：FIN、URG、ACK、PSH、RST、SYN 六个标记**全部置 1**（像圣诞树挂满灯）。**Null**：全部置 0。二者是 FIN 扫描的变种，**处理方式与 FIN 相同**，优缺点也相同。

**FTP 代理扫描**：利用 FTP 的代理连接选项——它允许客户端控制一个 FTP 服务器向另一个服务器传输数据。攻击者用 **PORT 命令**指定目标主机的端口 P，让 FTP 服务器去连；连上了就说明 P 开放。

## 三、优缺点对比

| 方法 | 优点 | 缺点 |
|---|---|---|
| Connect | 稳定可靠，**不需要特殊权限** | 不隐蔽：失败连接产生大量错误信息，成功连接易被追溯，易被防火墙和 IDS 发现 |
| SYN | **隐蔽**，未完成三次握手，不留痕迹、不被日志记录 | **需要 root 权限**才能构造 SYN 包 |
| FIN | 不属于建立连接的过程，比较隐蔽 | 监听状态不对 FIN 反应，**只能等超时，扫描变慢**；需构造专门数据包；**只适用 Unix，Windows 总是回 RST** |
| Xmas / Null | 同 FIN | 同 FIN |
| FTP 代理 | **难以跟踪，可穿越防火墙**（FTP 服务器与目标同处防火墙内网） | 一些 FTP 服务器**禁止代理连接** |
| UDP | 无需建连，可探 UDP 服务 | 判断易偏差（见下） |

## 四、UDP 扫描

UDP 没有连接建立过程，判据换成“有没有报错”：

- 目标端口**监听** → **不会做出任何响应**；
- 目标端口**关闭** → 返回 **ICMP_PORT_UNREACH** 错误。

表面上区分度很好，实际有两个坑：

- **UDP 数据包与 ICMP 错误消息在通信中都可能丢失**，不能保证到达 → 判断出现偏差；
- **大多数主机对 ICMP 错误信息的发送比例做了限制**（避免被当作反射源），连发几十个探测只会回来几条。

所以 UDP 扫描的结果只能作参考，通常要重发多次。

## 五、隐匿策略、Nmap 与防御

**四种隐匿策略**

1. **随机端口扫描**：不按 1、2、3 顺序扫，打乱顺序，让流量特征不像扫描。
2. **慢扫描**：拉长时间间隔，低于 IDS 的告警阈值。
3. **分片扫描**：**把 TCP 连接控制报文分成多个短 IP 报文段传送**。隐蔽性好、可穿越防火墙、躲避安全检测；缺点是**可能被进行排队过滤的防火墙丢弃**，且**某些程序处理这些小数据包时会出现异常**。
4. **诱骗（Decoy）**：伪造源地址混在真实扫描中，但**必须能监听/嗅探到**——否则收不到结果。

**Nmap**（Network Mapper，Fyodor 制作）三大功能：

- 探测一组主机是否**在线** → 主机扫描技术；
- 扫描主机**端口**，嗅探所提供的网络服务 → 端口扫描技术；
- 推断主机所用的**操作系统** → 远程 OS 指纹识别。

| 参数 | 作用 |
|---|---|
| `-sP` | Ping 扫描，看哪些机器 up |
| `-sT` | TCP connect 扫描 |
| `-sS` | TCP SYN 扫描 |
| `-sF` / `-sX` / `-sN` | FIN / Xmas / Null 扫描 |
| `-sU` | UDP 扫描 |

**扫描的防御**：反扫描技术、端口扫描监测工具、防火墙技术、审计技术，以及其他防御技术。

## 六、易错辨析

| 错误说法 | 判据 | 反例 |
|---|---|---|
| “SYN 扫描完成了三次握手” | 半开的定义是只到 SYN+ACK | 第三个 ACK 不发，服务端连接停在半连接队列，不落日志 |
| “FIN 扫描没响应就是端口关闭” | 判据正好相反 | 开放端口不理会 FIN，关闭端口才回 RST |
| “FIN 扫描对所有系统都有效” | 取决于协议栈实现 | Windows 对任何 FIN 都回 RST，结果全是“关闭” |
| “Connect 扫描需要 root” | 它调用系统 connect | 普通用户即可，需要 root 的是构造原始包的 SYN/FIN |
| “UDP 端口没响应就是关闭” | 无响应恰恰表示监听 | 关闭端口回 ICMP_PORT_UNREACH |
| “诱骗扫描只要伪造源地址就行” | 还要能收到回应 | 收不到回应就无法判断端口状态 |
| “Nmap 只能扫端口” | 三大功能 | 还能探主机是否在线、识别操作系统 |

### 简答题

<details class="ly-fold">
<summary>9 道简答题</summary>

**1.** 什么是端口？为什么端口扫描有意义？

**2.** 写出六种端口扫描方法的判据。

**3.** 比较 TCP Connect 与 SYN 扫描的优缺点。

**4.** FIN 扫描为什么“没响应就是开放”？它有哪些局限？

**5.** Xmas 与 Null 扫描与 FIN 扫描是什么关系？

**6.** 叙述 FTP 代理扫描的过程与优缺点。

**7.** UDP 扫描的判据是什么？为什么结果不可靠？

**8.** 四种扫描隐匿策略分别是什么？各有什么代价？

**9.** Nmap 有哪三大功能？写出六种扫描对应的参数。

---

**答案要点**

**1.** 端口是应用服务的唯一地址，是潜在的通信信道，也是入侵通道；16 位、0–65535，公认端口 0–1023。扫描端口能发现目标开放了哪些服务，从而推断可攻击面。

**2.** Connect：建连成功=开放，SOCKET_ERROR=关闭。SYN：SYN+ACK=开放，RST=关闭。FIN/Xmas/Null：无响应=开放，RST=关闭。FTP 代理：数据连接成功=开放。UDP：无响应=开放，ICMP_PORT_UNREACH=关闭。

**3.** Connect 稳定可靠、不需特殊权限，但不隐蔽，失败连接产生大量错误信息、成功连接易被追溯，易被防火墙和 IDS 发现。SYN 半开、不留痕迹、不被日志记录，但需要 root 权限构造原始包。

**4.** 依据 RFC 793：关闭端口收到 FIN 要回 RST，开放端口的监听进程不理会，因此“无响应”判为开放。局限：只能等超时，速度慢；需构造专门数据包；只适用 Unix，Windows 对 FIN 总回 RST。

**5.** 都是 FIN 扫描的变种，扫描过程与处理方式相同，关闭端口同样回 RST，优缺点也与 FIN 相同；区别只在标志位组合——Xmas 六个全置 1，Null 六个全置 0。

**6.** 利用 FTP 服务器的代理连接选项，用 PORT 命令指定目标主机的端口 P，让 FTP 服务器向该端口发起数据连接；连接成功说明端口开放。优点：难以跟踪，且当 FTP 服务器与目标同处防火墙内网时可穿越防火墙；缺点：部分 FTP 服务器禁止代理连接。

**7.** 判据：监听端口不响应，关闭端口返回 ICMP_PORT_UNREACH。不可靠原因：UDP 包与 ICMP 错误消息都可能丢失；大多数主机限制 ICMP 错误的发送比例，回应数量远少于探测数量。

**8.** 随机端口扫描（不按序，但仍需全扫，量大）、慢扫描（时间长）、分片扫描（隐蔽可穿防火墙，但可能被排队过滤的防火墙丢弃、部分程序处理小包异常）、诱骗（伪造源地址，但必须能监听回应）。

**9.** 探测主机是否在线（主机扫描）、扫描端口嗅探服务（端口扫描）、推断操作系统（OS 指纹）。参数：`-sP` ping、`-sT` connect、`-sS` SYN、`-sF` FIN、`-sX` Xmas、`-sN` Null、`-sU` UDP。

</details>

> **一句话总结**：端口扫描只有一句话——**看它回什么**：SYN 回 SYN+ACK 是开、FIN 不回是开、UDP 不回是开、关闭统统回 RST 或 ICMP 不可达。
