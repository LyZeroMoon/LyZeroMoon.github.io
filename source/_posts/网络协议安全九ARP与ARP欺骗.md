## 一、ARP 缓存表与报文

**ARP 缓存表**：存储其它主机或网关的 **IP 地址与 MAC 地址的对应关系**。每台主机、每个网关都有一张。每条记录就是一个"IP 地址—MAC 地址"对。

| 记录类型 | 能否被 ARP 应答包修改 |
|---|---|
| **静态** | **不能**被修改 |
| **动态** | **可以**被修改 |

这一行就是 ARP 欺骗的全部前提：只要记录是动态的，任何人发一个 ARP 应答就能把它改掉，**不需要先发请求**。

**ARP 报文的封装**：

| 协议 | 封装位置 |
|---|---|
| **ARP** | **直接加封以太网报头**，不放进 IP 报文 |
| ICMP | 封装在 IP 报文内部 |

所以 ARP 是**网络层要用的、却运行在链路层之上的协议**——它自己有以太网类型字段（0x0806），不需要 IP 首部。

**ARP 请求的广播地址**：用**二层 MAC 广播地址（全 F）**发送，**不是**三层 IP 广播地址。

- ARP 请求报文：目的 MAC 填全 F，目的 IP 填要查询的地址，自己的 IP 与 MAC 都填上；
- ARP 应答报文：目的 MAC 填请求方的 MAC，**单播**回去。

**两台主机的 ARP 报文对比**（以 10.10.1.1 查 10.10.1.2 为例）：

| | 目的 MAC | 源 MAC | 目的 IP | 源 IP |
|---|---|---|---|---|
| 请求 | FF:FF:FF:FF:FF:FF | 请求方 | 10.10.1.2 | 10.10.1.1 |
| 应答 | 请求方 MAC | 应答方 | 10.10.1.1 | 10.10.1.2 |

## 二、两类通信流程

### 同网段通信（主机 11 → 主机 33）

1. 通信前先查**自己的 ARP 缓存**里有没有 192.168.1.3 对应的 MAC；
2. 没有就向局域网的**广播地址（MAC 全 F）**发 ARP 请求：192.168.1.3 的 MAC 是什么，请告诉 192.168.1.1；
3. 广播到达所有主机，**只有** 192.168.1.3 响应，回一个 ARP 应答，告知自己的 MAC；
4. 主机 11 拿到地址，把对应关系写进自己的 ARP 缓存；
5. 之后双方靠缓存表通信，**直到通信停止后两分钟**，这条记录才被删除。

关键点：**广播是二层行为，交换机收到广播帧要向所有端口泛洪**——这就是为什么同网段里任何一台机器都能看到别人的 ARP 请求。

### 跨网段通信（主机 11 → 另一网段的主机 33）

1. 主机 11 发现目的 IP **不在自己网段**，必须由网关转发；
2. 于是查缓存里有没有**网关** 192.168.1.10 的 MAC，没有就 ARP 请求获得；
3. 帧的目的 MAC 填**网关的 MAC**，目的 IP 仍是最终主机 33；
4. 网关 D 收到后按路由转发到网关 E；
5. 网关 E 查**自己的** ARP 缓存找 10.1.1.3 的 MAC，没有就 ARP 请求，然后用该 MAC 发给主机 33。

**必须记住的一条**：跨网段时，源/目的 **IP 不变**（端到端），但**目的 MAC 每跳都换**（下一跳的 MAC）。主机根本不知道远端主机的 MAC，它只需要网关的 MAC。

## 三、ARP 欺骗

**原理**：攻击者不发请求，直接发**伪造的 ARP 应答**，把受害主机缓存里的某条记录改成自己的 MAC。

**两步伪造 + 三步流程**（三台主机 A、B、C 加路由器 R）：

**步骤 1**：攻击者 C 向 **A 和 B 各发一个 ARP 欺骗报文**：

| 发给谁 | 报文内容 | 后果 |
|---|---|---|
| 发给 A | "10.10.10.2（B）的 MAC 是 CC" | A 的缓存里 B 指向 C |
| 发给 B | "10.10.10.1（A）的 MAC 是 CC" | B 的缓存里 A 指向 C |

这叫**双向欺骗**。如果只骗一方，就只有单向流量经过攻击者。

**步骤 2**：A 与 B 之间的帧全部送到 C，**攻击者从网络接口嗅探**。

**步骤 3**：攻击者再把嗅探到的数据**发回**原本该收的主机（把目的 MAC 改回去），通信看起来正常，受害者毫无察觉，攻击者继续下一轮。

**为什么要骗网关**（PPT P62 的问题：需要监听主机与外界之间的通信怎么办）：因为**路由器或网关是内网与外网之间报文转发的必经节点**。攻击者向全网段广播伪造应答，宣称"网关 10.10.10.8 的 MAC 是我"，所有主机的出网流量就都先到攻击者手里，再转发给真网关——这就是最经典的**中间人**布置。

**危害四条**（PPT 原文口径）：

1. 致使同网段其它用户**无法正常上网**（频繁断网或网速慢）；
2. 可以**嗅探交换式局域网内所有数据包**，得到敏感信息；
3. 可以对信息进行**篡改**，例如在你访问的网页里插入广告；
4. 可以**控制局域网内任何主机**，起到"网管"的作用，例如让某台主机不能上网。

## 四、检测与防御

**检测三法**：

| 方法 | 判据 |
|---|---|
| 现象观察 | 网络频繁掉线、网速突然变慢 |
| `arp -a` 对比 | 列出网关 MAC 与**已知的正确 MAC** 不同，那个 MAC 就是攻击主机 |
| 抓包 | 用 sniffer 发现局域网内存在**大量 ARP reply** 包，包中指定的 MAC 即攻击主机 |

**防御四法**：

| 方法 | 原理 |
|---|---|
| **MAC 地址绑定** | 使每台机器的 IP 与硬件地址一一对应，不可更改 |
| **静态 ARP 缓存** | 手工更新记录，ARP 应答改不动静态项，欺骗无法进行 |
| **ARP 服务器** | 由服务器统一查转换表响应 ARP 广播；前提是**这台服务器不被攻破** |
| **ARP 防护软件** | 如 ARP 防火墙 |

**为什么这四条都不是根本解**：前两条靠管理成本（每台机器手工配）；第三条把信任集中到一台服务器上，服务器被黑就全盘皆输；第四条只是终端自保。真正在交换机侧做的是 **DHCP Snooping + 动态 ARP 检测（DAI）**，把"IP—MAC—端口"三者绑在接入设备上。

## 五、易错辨析

| 错误说法 | 判据 | 反例 |
|---|---|---|
| "ARP 欺骗要先发 ARP 请求" | 应答就能改缓存 | 攻击者直接单播伪造应答，受害者连请求都没发 |
| "ARP 请求用 IP 广播地址" | 用的是 MAC 全 F | 三层广播 255.255.255.255 不是 ARP 请求的目的地址 |
| "ARP 封装在 IP 包里" | 直接加以太网头 | 以太网类型 0x0806，没有 IP 首部；ICMP 才在 IP 里 |
| "跨网段时目的 IP 会被改成网关 IP" | IP 端到端不变 | 改的只有目的 MAC，IP 一直是最终主机 |
| "静态 ARP 记录也会被应答覆盖" | 静态项不可改 | 正因如此静态绑定才有效 |
| "ARP 欺骗只能单向" | 双向欺骗才形成完整中间人 | 只骗 A 的话，B 的回包直接回 A，不走 C |
| "ARP 有认证机制" | ARP 无任何认证 | 谁发的都信，这是设计缺陷 |

### 简答题

<details class="ly-fold">
<summary>9 道简答题</summary>

**1.** ARP 缓存表是什么？静态与动态记录有什么区别？

**2.** ARP 报文封装在哪一层？与 ICMP 有什么不同？

**3.** ARP 请求使用什么地址发送？为什么不用 IP 广播地址？

**4.** 叙述同网段两台主机首次通信的完整过程。

**5.** 叙述跨网段通信的过程，并说明为什么要查网关的 MAC。

**6.** 完整叙述 ARP 欺骗的原理与三个步骤。

**7.** 为什么攻击者常把网关作为欺骗对象？

**8.** ARP 欺骗有哪些危害？如何检测？

**9.** ARP 欺骗有哪些防御手段？各自的局限是什么？

---

**答案要点**

**1.** ARP 缓存表存放本机已知的"IP—MAC"对应关系，用于把目的 IP 换成目的 MAC。静态记录由人工配置，ARP 应答包无法修改；动态记录由 ARP 应答自动学习，可以被任何应答覆盖或刷新——这是 ARP 欺骗可行的直接原因。

**2.** ARP 报文直接加封以太网报头，以太网类型字段为 0x0806，不进入 IP 报文。ICMP 则封装在 IP 报文内部（协议号 1）。也就是说 ARP 是"给网络层用的、却跑在链路层"的协议。

**3.** 用二层 MAC 广播地址（全 F）。因为在发出请求时主机还不知道目标的 MAC，而它需要的正是这个地址；三层 IP 广播 255.255.255.255 只在 IP 层有意义，帧的目的 MAC 仍要填全 F。ARP 工作在二层寻址，所以用它自己的广播方式。

**4.** ① 查本机 ARP 缓存有无目标 IP；② 无则向 MAC 全 F 发 ARP 请求；③ 广播被网内所有主机收到，只有目标主机应答，单播回自己的 MAC；④ 请求方把对应关系写入缓存；⑤ 之后靠缓存通信，停止通信两分钟后记录被删除。

**5.** 主机发现目的 IP 不在本网段，只能交给网关。于是查缓存中网关的 MAC（没有就 ARP 请求），把帧的目的 MAC 填成网关 MAC 发出去。网关按路由转发到下一跳，再由对端网关 ARP 查出最终主机 MAC 送达。原因是：**MAC 只在本地链路有效**，跨网段必须逐跳重写目的 MAC，主机只需要知道第一跳（网关）的 MAC。

**6.** 原理：ARP 无认证，主机收到 ARP 应答就更新动态缓存。步骤：① 攻击者向 A 和 B 分别发送伪造应答，声称对方的 IP 对应攻击者的 MAC，双向改写缓存；② A、B 之间（或与网关）的帧全部被交换机送到攻击者端口，攻击者嗅探；③ 攻击者把数据转发给真正的接收者，通信表面正常，循环进行下一轮。

**7.** 因为路由器/网关是内网与外网之间报文转发的必经节点。骗到网关这一条记录，就能让整个网段所有主机的出网流量都先经过攻击者，一次布置覆盖全网，比逐个骗主机高效得多。

**8.** 危害：同网段用户频繁断网或变慢；可嗅探交换式局域网内所有数据包获取敏感信息；可篡改信息（如在网页中插广告）；可控制网内任何主机、让对方不能上网。检测：观察频繁掉线与变慢；用 `arp -a` 比对网关 MAC 与正确值；用抓包工具发现大量 ARP reply。

**9.** 四条：MAC 地址绑定（一一对应不可改）、静态 ARP 缓存（应答改不动）、ARP 服务器统一应答、ARP 防护软件。局限：前两条要在每台机器上手工维护，规模大时成本高；ARP 服务器把信任集中到单点，服务器被攻破则全网失守；防护软件只能终端自保。工程上更彻底的是交换机侧 DHCP Snooping + DAI，把 IP、MAC、端口三者绑定。

</details>

> **一句话总结**：ARP 无认证、应答就能改缓存，这是欺骗的前提；二层全 F 广播请求、单播应答；跨网段 IP 不变而 MAC 逐跳变；防御的本质是把"动态"变"静态"、把"信任"变成"绑定"。
