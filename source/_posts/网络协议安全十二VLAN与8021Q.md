## 一、为什么要有 VLAN

**根本原因是广播风暴**：交换机的所有端口默认同属一个广播域，任何广播帧都向全端口泛洪，主机一多、广播一多，带宽被无效帧吃光。

**传统解法是路由器分段**：路由器不转发广播，能把一个广播域切成两个。但路由器端口少、成本高、转发慢，靠它频繁分段不现实。VLAN 就是在交换机内部做"逻辑分段"。

**五条优点**：

| 优点 | 含义 |
|---|---|
| 隔离广播域 | 抑制广播报文，这是首要目的 |
| 减少移动和改变的代价 | 换部门不用重新布线 |
| 创建虚拟工作组 | 按职能组网，超越物理位置 |
| 增强通讯的安全性 | 不同 VLAN 默认不能互通 |
| 增强网络的健壮性 | 一个 VLAN 内的故障不易扩散 |

## 二、四种划分方法

| 方法 | 依据 | 类型 | 优点 | 缺点 |
|---|---|---|---|---|
| **基于端口** | 交换机端口 | 静态 | 定义成员非常简单，指定端口即可 | 用户离开原端口到新交换机端口，**必须重新定义** |
| **基于 MAC 地址** | 源 MAC | 动态 | 位置移动不用重配，是"基于用户"的 VLAN | 初始化配置量极大；交换机效率降低；一个端口可能属于多个 VLAN，**无法限制广播包** |
| **基于协议** | 二层帧的协议字段 | — | 按协议分流 | 实际应用**很少** |
| **基于子网** | IP 网段 | — | 用户可在网内自由移动，不用重配工作站 | 要三层交换机，检查每个包的网络层地址**很费时**；一个端口多 VLAN，**无法有效抑制广播** |

**记忆抓手**：**基于端口最省事但最死板；基于 MAC 最灵活但最费配置**。四种里只有"基于协议"基本不用。

## 三、二层、三层与路由器

**二层交换机**：

- 对网络层及高层**透明**，不处理 IP 地址、不处理 TCP/UDP 端口，只看 MAC，交换靠**硬件**实现，速度相当快；
- **不能处理不同 IP 子网（包括 VLAN）之间的数据交换**。

**路由器**：

- 设计初衷是满足不同类型网络的连接，优势在选择最佳路由、负荷分担、链路备份、路由信息交换；
- 注意一句易错的话：**不是路由器不交换，而是到了路由器必须先做三层寻址（软件），改完二层 MAC 再"交换"**；
- 能处理大量跨子网数据包，但**转发效率比二层低**。

**三层交换 = 二层交换技术 + 三层转发技术**，目的就是"既要二层的高效，又要能跨子网"。

**工作原理（第一个包与后续包不同）**：

第一个包的目的 MAC 是交换机自己，交给 IP 层后发现目的 IP 不是自己 → 查**硬件转发表**（集成在 ASIC 转发卡中），表里没有 → 交给**路由进程（CPU）**：查路由表找下一跳 IP → 用 ARP 求下一跳 MAC → 转发出去。

这一趟里交换机至少做**三件事**：

| # | 做的事 |
|---|---|
| 1 | 修改 IP 包头的 **TTL** |
| 2 | 修改**源 MAC**，改成自己出接口的 MAC |
| 3 | 建立**硬件转发表项**：目的 IP、（下一跳）目的 IP 对应的 MAC、MAC 对应的 VLAN、对应端口 |

之后再来的包直接查硬件转发表转发，**不再过 CPU、不再查路由表**——这就是"**一次路由，多次转发（交换）**"。

**关键点**：三层交换机判断目的 IP 不是自己时，**不查路由表、不查 ARP 表、不查 MAC 表，只查硬件转发表**。只有转发表没命中才落到 CPU。

## 四、链路与端口类型

**VLAN 可以跨越交换机**：VLAN 数据可经多台交换机传递，但**不同 VLAN 的信息必须经过三层路由处理**才能转发到某个接入端口上。

| 链路类型 | 连接对象 | 是否属于某个 VLAN | 帧是否带标记 |
|---|---|---|---|
| **接入链路 Access-Link** | 主机与交换机 | 属于且**只能属于一个 VLAN** | 收发都是**无标记**的普通以太网帧 |
| **干道链路 Trunk-Link** | 交换机之间、交换机与路由器之间 | **不属于**任何具体 VLAN | 承载多个 VLAN，**打标记**的帧 |

Access 端口的约束：不能直接接收其它 VLAN 的信息，也不能直接向其它 VLAN 发送信息——**跨 VLAN 必须走三层**。

**三种端口**：

| 端口 | 用途 | 可属于 VLAN 数 | 不打标签的报文 |
|---|---|---|---|
| **Access** | 接用户计算机 | **1 个** | 全部（本来就是 untagged） |
| **Trunk** | 交换机之间 | 多个 | **只允许缺省 VLAN** 的报文不打标签 |
| **Hybrid** | 两者皆可 | 多个 | **可以允许多个 VLAN** 不打标签 |

Hybrid 与 Trunk 的唯一实质区别就在最后一行；另外**同一台交换机上 Hybrid 与 Trunk 不能并存**。

**帧在网络中的变化**：

1. 主机不知道 VLAN 的存在，发出的是 **untagged** 报文；
2. 交换机按配置（端口归属）判断报文属于哪个 VLAN；
3. 在**干道链路**上发送时**打上 VLAN 标记**，让对端交换机知道归属；
4. 发给主机之前**剥离标记**，还原成普通以太网帧。

## 五、Native VLAN 与 802.1Q 转发原则

**Native VLAN（本征 VLAN）**：可以在 Trunk 链路上指定一个，**默认 VLAN 1**。来自 Native VLAN 的帧通过 Trunk 时**不重新封装**，以原有帧传输。

**端口缺省 ID（PVID）**：

- Access 端口只属于一个 VLAN，**缺省 ID 就是它所在的 VLAN，不用设置**；
- Trunk 端口属于多个 VLAN，**需要设置缺省 VLAN ID，缺省为 VLAN 1**；
- 命名差异：**华为叫 Pvid Vlan，思科叫 Native Vlan**，指的是同一件事。

**802.1Q 四条转发原则**（最常考的一张表）：

| 场景 | 收到无标记帧 | 收到有标记帧 | 发送时 |
|---|---|---|---|
| **Access 端口** | 打上该端口的 **PVID** | 与端口标签**相同**则转发，**不同**则**丢弃** | **剥离** VLAN 信息，发出普通以太网帧 |
| **Trunk 端口** | 归入**缺省 VLAN**，转发到属于该 VLAN 的端口（打标签） | **不改变**，原样透传 | VLAN 与 PVID **不同** → 直接透传（带标签）；与 PVID **相同** → **剥离**标签再发 |

一句话版本：**Access 只进一个 VLAN、出去一定剥标签；Trunk 靠标签区分、只有等于 PVID 时才剥标签。**

## 六、易错辨析

| 错误说法 | 判据 | 反例 |
|---|---|---|
| "VLAN 能隔离冲突域" | VLAN 隔离的是**广播域** | 冲突域早被交换机每端口一个分掉了 |
| "VLAN 之间天然能通" | 默认隔离，必须三层转发 | 需要三层交换机或路由器 |
| "基于 MAC 划分能抑制广播" | 一个端口可能属于多 VLAN | 正是它的缺点之一 |
| "Access 端口可以属于多个 VLAN" | 只能一个 | 要多个得用 Trunk 或 Hybrid |
| "Trunk 端口属于某个 VLAN" | Trunk 不属于任何具体 VLAN | 它承载多个 VLAN |
| "三层交换机第一个包也查硬件转发表就够" | 首包未命中要上 CPU | 查路由表 + ARP + 建表项 |
| "Hybrid 和 Trunk 可以同时配在一台交换机" | 不能并存 | 同一交换机上互斥 |
| "华为的 PVID 和思科的 Native VLAN 是两回事" | 同一概念 | 只是厂商叫法不同 |

### 简答题

<details class="ly-fold">
<summary>9 道简答题</summary>

**1.** VLAN 为什么会出现？解决什么问题？

**2.** 列举 VLAN 的五条优点。

**3.** 比较四种 VLAN 划分方法的优缺点。

**4.** 二层交换机、路由器、三层交换机各自的能力边界是什么？

**5.** 叙述三层交换机"一次路由、多次转发"的过程。

**6.** 三层交换机转发第一个包时做了哪三件事？

**7.** 比较 Access 链路与 Trunk 链路。

**8.** 比较 Access、Trunk、Hybrid 三种端口。

**9.** 写出 802.1Q 在 Access 与 Trunk 端口上的四条转发原则。

---

**答案要点**

**1.** 交换机所有端口默认同处一个广播域，主机增多后广播帧泛洪会形成广播风暴、耗尽带宽。用路由器分段有效但端口少、成本高、速度慢。VLAN 在交换机内部把端口逻辑分组，用软件手段把广播域切开，既隔离广播又不增加硬件。

**2.** 隔离广播域、抑制广播报文；减少移动和改变的代价；创建虚拟工作组，超越传统网络工作方式；增强通讯安全性；增强网络健壮性。

**3.** 基于端口：最简单，指定端口即可，但用户换端口要重配。基于 MAC：位置移动不用重配、是"基于用户"的，但初始化配置量大、效率降低、一个端口属多 VLAN 无法限制广播。基于协议：按二层协议字段划分，实际几乎不用。基于子网：用户可自由移动，但要三层交换机、逐包查网络层地址很费时，且无法有效抑制广播。

**4.** 二层交换机对网络层透明，只看 MAC、硬件转发、速度快，但不能处理不同 IP 子网（含 VLAN）之间的交换。路由器能做三层寻址与路由选择、可跨异构网络，但转发效率低于二层。三层交换机把二者结合：硬件转发保速度，具备路由能力可跨 VLAN/子网，适合大型局域网内部。

**5.** 首包的目的 MAC 是交换机自己，上送 IP 层发现目的 IP 非本机，查硬件转发表未命中，交 CPU 处理：查路由表定下一跳、ARP 求下一跳 MAC、发出，同时把结果写进硬件转发表。后续同流向的包直接匹配硬件转发表，由 ASIC 高速转发，不再进 CPU、不再查路由表。

**6.** ① 修改 IP 首部的 TTL（减一，防环）；② 修改源 MAC 为自己的出接口 MAC；③ 建立硬件转发表项，记录目的 IP、下一跳 IP 对应的 MAC、MAC 所属 VLAN、出口端口。

**7.** Access 链路连接主机与交换机，端口只属于一个 VLAN，收发都是无标记的普通以太网帧，跨 VLAN 必须经三层转发。Trunk 链路连接交换机之间或交换机与路由器，不属于任何具体 VLAN，可承载多个 VLAN，帧必须打上 802.1Q 标记以便对端识别，只有缺省 VLAN 的报文不打标签。

**8.** Access：接用户，只能属于 1 个 VLAN，收发均为 untagged。Trunk：接交换机，可属多个 VLAN，只允许缺省 VLAN 的报文不打标签。Hybrid：两种场合都可用，可属多个 VLAN，且允许多个 VLAN 的报文不打标签；同一交换机上 Hybrid 与 Trunk 不能并存。

**9.** Access 收：无标记则打上端口 PVID；有标记则与端口标签相同才转发、不同则丢弃。Access 发：剥离 VLAN 信息。Trunk 收：无标记归入缺省 VLAN 并打标签转发；有标记则不改变。Trunk 发：VLAN 与 PVID 不同则直接透传（带标签）；相同则剥离标签后发送。

</details>

> **一句话总结**：VLAN 为隔离广播而生；四种划分只有端口与 MAC 常用；跨 VLAN 必须三层，"一次路由多次转发"的核心是首包建表、后续查 ASIC；Access 出去必剥标签，Trunk 只有等于 PVID 时才剥。
