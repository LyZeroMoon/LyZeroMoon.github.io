## 一、攻击过程与扫描

**一般攻击过程（七阶段，按序）**

网络侦查 → 远端扫描 → 网络渗透 → 权限获取 → 维持破坏 → 设置后门 → 毁踪灭迹。

英文对照常考填空：Network Investigation、Remote Scanning、Network Penetration、Access Gaining、Maintenance Destruction、Backdoors Creating、Tracks Covering。

**网络扫描**：使用网络扫描软件对特定目标进行各种**试探性通信**，以获取目标信息的行为。

**四个目的**（对应四类扫描）：

| 目的 | 扫描类型 |
|---|---|
| 识别目标主机的工作状态（开 / 关机） | 主机扫描 |
| 识别目标主机端口的状态（监听 / 关闭） | 端口扫描 |
| 识别目标主机的操作系统类型 | 操作系统识别 |
| 识别目标系统可能存在的漏洞 | 漏洞扫描 |

**主机扫描**：向目标主机发送探测数据包，**根据是否收到响应**判断主机的工作状态。四条技术路线：ICMP Echo、ICMP Non-Echo、异常的 IP 数据报首部、错误的分片。

## 二、ICMP 基础

**作用**：提高 IP 报文交付成功的机会。网关或目标机器利用 ICMP 与源通信；出现问题时提供反馈信息用于报告错误。

**报文结构**：IP 首部 + ICMP 报文。ICMP 前 4 个字节固定为**类型（8 位）、代码（8 位）、检验和（16 位）**，后 4 个字节的含义**取决于类型**，再往后是数据部分（长度也取决于类型）。

**类型值（必背）**

| 类别 | 类型值 | 名称 |
|---|---|---|
| 差错报告 | 3 | 终点不可达 |
| 差错报告 | 4 | 源站抑制 |
| 差错报告 | 11 | 时间超过 |
| 差错报告 | 12 | 参数问题 |
| 差错报告 | 5 | 改变路由 |
| 询问 | 8 或 0 | 回送请求或回答 |
| 询问 | 13 或 14 | 时间戳请求或回答 |
| 询问 | 17 或 18 | 地址掩码请求或回答 |
| 询问 | 10 或 9 | 路由器询问或通告 |

记法：差错 5 个（3、4、5、11、12），询问 4 组且都是“请求 / 回答”成对。

## 三、ICMP Echo 扫描

**判据**：发 ICMP 回送请求（type 8）。

- 收到**回送响应**（type 0）→ 目标主机**在运行**；
- **未收到任何响应** → 目标主机**未开机**。

这就是 `ping`。`ping` 通说明在运行；`Request timed out` 按 PPT 口径判为未开机——但严格说也可能是被过滤，这一点在下面“ICMP 的问题”里补上。

**Broadcast ICMP 扫描**：把 ICMP 请求包的目标地址设为**广播地址**，即可探测整个广播域/网段内的主机。

两个缺点（必考）：

- **只适合 UNIX/Linux** 系统，**Windows 会忽略**这种请求包；
- 容易引起**广播风暴**。

## 四、Non-Echo 与 ICMP 的困境

**ICMP Non-Echo 扫描**：不用回送请求，改用**其他类型的 ICMP 报文**（时间戳、地址掩码、路由器询问等）探测。目标对这些询问的应答同样说明主机在运行。

**ICMP 扫描的问题**：

- 很多企业防火墙对 **ICMP 回送请求**报文进行过滤，使其无法到达目标主机；
- 主机上安装的个人防火墙往往也**对 ICMP 报文进行阻断**。

→ 两种失败都表现为“无响应”，与“未开机”无法区分，这就是**假阴性**。解决办法：改用 **IP 数据报**扫描。

## 五、基于 IP 异常分组的扫描

思路：故意发一个**按标准必须回 ICMP 差错报文**的包，只要收到差错报文，就证明主机活着。

**（1）异常的 IP 数据报首部：参数错**

主机收到首部异常（**首部长度字段、IP 选项字段、版本号**）的 IP 数据报时，**应当返回“参数问题”（type 12）**的 ICMP 报文。

- 收到“参数问题”→ 在运行；
- 未收到任何响应 → 未开机。

**（2）错误的分片**

把一个 IP 数据报拆成几片，**只发第一片和第三片，故意不发第二片**。目标重组超时后，**应当回应“分片重组超时”的 ICMP 报文**。

- 收到该报文 → 在运行；
- 未收到 → 未开机。

两类的判据完全一致：**不是看“回什么内容”，而是看“有没有 ICMP 差错报文”**。这也是它们能绕过“过滤回送请求”的原因——防火墙通常只封 type 8，不封差错报文。

## 六、反向映射探测

适用场景：**目标主机无法从外部直接到达**，被过滤设备或防火墙保护。

做法：

- 推测可能的内部 IP 地址（列一张表），向这些地址逐个发送数据包；
- 目标网络的**路由器**收到后会做 IP 识别并转发，对**不在其服务范围**的 IP 包，返回 **ICMP Host Unreachable** 或 **ICMP Time Exceeded** 错误报文；
- 因此，**没有收到错误报文的 IP 地址，可认为在该网络中**（存在）。

局限：这种方法**同样受过滤设备的影响**——如果中间设备把差错报文也过滤掉，就全判为“在网络中”，结果失真。

注意判据方向与前面相反：前面是“有响应 = 活”，这里是“**没报错 = 存在**”。

## 七、易错辨析

| 错误说法 | 判据 | 反例 |
|---|---|---|
| “ping 不通就是没开机” | 无响应有两种原因 | 防火墙封了 type 8，主机明明在运行——改发首部异常包即可探到 |
| “主机扫描就是端口扫描” | 一个看主机活不活，一个看端口开不开 | 主机扫描只发 ICMP 或异常 IP 包，不碰端口 |
| “广播 ICMP 对所有系统都有效” | Windows 忽略广播请求 | 只适合 UNIX/Linux，且易引起广播风暴 |
| “异常首部包应回终点不可达” | 差错类型要看原因 | 首部长度/选项/版本异常 → 参数问题（12）；找不到目的网 → 终点不可达（3） |
| “错误分片应回时间超过” | 分片有专门的差错 | 重组超时回“分片重组超时”；TTL 耗尽才回“时间超过”（11） |
| “反向映射收到回应才算存在” | 判据是“有没有报错” | 没收到 Host Unreachable 才说明地址在网络中 |

### 简答题

<details class="ly-fold">
<summary>9 道简答题</summary>

**7.** 错误分片扫描怎么做？判据是什么？

**8.** ICMP 扫描为什么会失效？怎么解决？

---

**答案要点**

**1.** 网络侦查、远端扫描、网络渗透、权限获取、维持破坏、设置后门、毁踪灭迹。

**2.** 定义：使用网络扫描软件对特定目标进行各种试探性通信，以获取目标信息的行为。目的：识别主机工作状态、识别端口状态、识别操作系统类型、识别可能存在的漏洞。

**3.** 定义：向目标主机发送探测数据包，根据是否收到响应判断工作状态。路线：ICMP Echo、ICMP Non-Echo、异常的 IP 数据报首部、错误的分片。

**4.** 发 type 8 回送请求：收到 type 0 回送响应 → 在运行；无任何响应 → 未开机。误判：防火墙或主机防火墙过滤 ICMP 时同样表现为无响应，会把在运行的主机判为未开机（假阴性）。

**5.** 把请求包的目标地址设为广播地址，一次探测整个广播域。缺点：只适合 UNIX/Linux，Windows 忽略该请求包；大量回应容易引起广播风暴。

**6.** 首部长度字段、IP 选项字段、版本号异常时，主机按标准必须返回“参数问题”（type 12）的 ICMP 报文；只要收到该报文即证明主机在运行。它绕过了防火墙通常只封 type 8 的限制。

**7.** 把数据报拆成多片，故意只发第一片和第三片、不发第二片；目标重组超时后应返回“分片重组超时”的 ICMP 报文。收到 → 在运行；未收到 → 未开机。

**8.** 企业防火墙过滤 ICMP 回送请求，个人防火墙也常阻断 ICMP，导致探测包到不了或回应出不来。解决办法：改用 IP 数据报扫描（异常首部、错误分片）。

**9.** 目标无法从外部直接到达时，推测内部可能的 IP 地址列表并向其发包；目标网络路由器识别后转发，对不在其服务范围的地址返回 ICMP Host Unreachable 或 Time Exceeded。判据：没有收到错误报文的地址可认为在该网络中；该方法同样受过滤设备影响。
