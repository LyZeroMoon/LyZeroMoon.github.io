## 一、协议与七层

**网络协议**：网络设备之间通信规则的正式描述。三要素——**语法**（格式）、**语义**（含义）、**时序**（先后）。

**协议 ≠ 接口**：协议约束对等层，接口只描述上下层怎么调用。

**OSI 参考模型**：ISO 于 1984 年提出，目的是解决网络之间的兼容性问题。四条原则：层间边界清晰；每层实现特定功能；便于制定国际标准；层数足够多以免功能重复。

| 层 | 功能 | TCP/IP | PDU |
|---|---|---|---|
| 7 应用层 | 提供应用程序间通信 | 应用层 | 报文 / APDU |
| 6 表示层 | 处理数据格式、数据加密 | 应用层 | — |
| 5 会话层 | 建立、维护和管理会话 | 应用层 | — |
| 4 传输层 | 建立主机端到端连接 | 传输层 | 段 / 数据报 |
| 3 网络层 | 寻址和路由选择 | 网络层 | 报文（packet） |
| 2 数据链路层 | 提供介质访问、链路管理 | 链路层 | 帧 |
| 1 物理层 | 比特流传输 | 链路层 | 比特 |

两个易错点：TCP/IP **不是少三层，是合并**（会话层、表示层并进应用层）；最底层叫“链路层”时通常**含物理层**。

**LAN 与 WAN（背景考点）**

- **LAN**：几公里以内、经介质互联的设备集合；距离短、延迟小、速率高、传输可靠；设备为线缆、网卡、集线器、交换机、路由器；拓扑分总线型、星型——**拓扑指逻辑结构，与物理构型无关**。
- **WAN**：大范围提供数据通信，用于互连 LAN；结构 = 末端系统 + 通信系统；通信系统含 PSTN、ISDN、DDN、X.25、帧中继、ATM、PON；拓扑分星型、树型、全网状、半网状。
- **两种交换**：电路交换（时延小、透明传输；带宽固定、利用率低）／分组交换（多路复用、利用率高；实时性差）。

## 二、封装与四个数字

**对等通信**：每层用下一层提供的服务，与对方同一层通信。**封装**：每层把上层交来的数据整体当作数据，加上本层首部。

| 步骤 | 产物 | 长度 |
|---|---|---|
| 应用数据 | 用户数据 | $n$ |
| 加 TCP 首部 | TCP 段 | $n+20$ |
| 加 IP 首部 | IP 数据报 | $n+40$ |
| 加以太网首尾 | 以太网帧 | $n+58$ |

四个数字，考试常混：

- **MTU 1500**：IP 数据报上限（即以太网帧载荷上限）。
- **MSS 1460**：TCP 载荷上限 = 1500 − 20 − 20。
- **最小载荷 46**：帧载荷不得少于 46 字节，不足补零（帧长 ≥ 64）。
- **首部开销 58**：14 + 20 + 20 + 4。

例：100 字节数据 → 最终帧 158 字节，首部占 36.7%。换 UDP 则为 $n+46$，载荷上限 1472。

<details class="ly-fold">
<summary>46 与 64 的来源</summary>

10 Mbit/s 以太网用 CSMA/CD，发送方必须还在发送时就能听到冲突。往返时延上限 51.2 μs 折合 512 bit = 64 字节，即最小帧长；减去 14 + 4 = 18 字节首尾，载荷最少 46。千兆全双工后不再需要冲突检测，下限保留为兼容。

</details>

## 三、各层协议

**应用层**：文件传输 FTP、TFTP；邮件 SMTP、POP3；网络管理 SNMP、Telnet、Ping、Tracert；网络服务 HTTP、DNS。

**传输层**：

| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠，不保证送达 |
| 机制 | 序号 + 确认；窗口流控；全双工 | 无 |
| 适用 | 要求得到响应的应用 | 小量数据，可靠性交上层 |

**端口号**：16 位，0–65535，标识上层应用；公认端口 0–1023。IP 用**协议号**区分传输层协议：TCP = 6，UDP = 17。

| 服务 | HTTP | FTP | Telnet | SMTP | DNS | TFTP | SNMP |
|---|---|---|---|---|---|---|---|
| 端口 | 80 | 20/21 | 23 | 25 | 53 | 69 | 161 |

**首部字段**：TCP 固定 20 字节——源/目的端口（各 16 位）、序号、确认号、首部长度、标志位（URG/ACK/PSH/RST/SYN/FIN）、窗口、校验和、紧急指针。UDP 固定 8 字节——源端口、目的端口、长度、校验和。

**网络层**：IP（无连接、不可靠，与路由协议协同选路）；ARP（IP → MAC）；RARP（MAC → IP）；ICMP（控制与差错报文，含**源抑制**）；IGMP（组播）。IP 首部含版本、首部长度、总长度、标识、标志、片偏移、TTL、协议、校验和、源/目的地址。

## 四、三次握手与四次挥手

| 三次握手 | 方向 | 报文 |
|---|---|---|
| 1 | 客户端 → 服务器 | SYN，seq = x |
| 2 | 服务器 → 客户端 | SYN + ACK，seq = y，ack = x + 1 |
| 3 | 客户端 → 服务器 | ACK，ack = y + 1 |

| 四次挥手 | 方向 | 报文 |
|---|---|---|
| 1 | 主动方 → 被动方 | FIN |
| 2 | 被动方 → 主动方 | ACK |
| 3 | 被动方 → 主动方 | FIN |
| 4 | 主动方 → 被动方 | ACK |

<details class="ly-fold">
<summary>为什么三次、为什么四次</summary>

两次不够：只有 SYN 与 SYN+ACK，服务器无法确认客户端收到了自己的 SYN，一个延迟的旧 SYN 就能让它单方建连接、空占资源。第三次 ACK 让**双方都确认对方收发正常**。

四次是因为全双工，两个方向各关一次：被动方收到 FIN 只表示对方不发了，自己可能还有数据，于是先 ACK、发完再 FIN。无数据可发时 ACK 与 FIN 可合并，退化成三次。

</details>

## 五、易错辨析

| 错误说法 | 判据 | 反例 |
|---|---|---|
| “TCP/IP 比 OSI 少三层” | 比功能不比层数 | 表示层、会话层的活并进了应用层，没消失 |
| “封装就是加密” | 封装加的是明文首部 | 抓包可见源 MAC、源 IP、目的端口，改完重算校验和即可发出 |
| “端口号标识主机” | 端口标识进程，主机靠 IP | 两台服务器都监听 80，端口完全相同 |
| “MTU 1500 是 TCP 段上限” | 1500 是 IP 数据报上限 | TCP 段最大 1480，MSS 1460 |
| “UDP 首部也是 20 字节” | UDP 首部只有 4 个字段 | 8 字节，载荷上限 1472 |

### 判断题

对错先在纸上写，再展开对答案。

<details class="ly-fold">
<summary>10 道判断题</summary>

**1.** TCP/IP 的应用层只对应 OSI 的应用层。

**2.** 协议与接口是同一个概念。

**3.** 封装会把首部隐藏起来，第三方读不到源 MAC 地址。

**4.** 以太网帧的载荷可以是 20 字节。

**5.** MTU 为 1500，表示 TCP 一次最多能发 1500 字节数据。

**6.** UDP 没有连接，所以不需要端口号。

**7.** IP 提供无连接、不可靠的服务。

**8.** ARP 的作用是把 IP 地址解析为 MAC 地址。

**9.** ICMP 是传输层协议。

**10.** 四次挥手时，若被动方没有数据要发，ACK 与 FIN 可以合并，退化成三次。

---

**答案**

1. 错。对应 5、6、7 三层，是合并不是删掉。
2. 错。协议约束对等层，接口只描述上下层怎么调用。
3. 错。首部是明文，抓包就能读到源 MAC、源 IP、目的端口。
4. 错。载荷最少 46 字节，不足补零填充。
5. 错。1500 是 IP 数据报上限，TCP 载荷上限是 1460。
6. 错。UDP 首部就有源/目的端口各 16 位，无连接只是不建状态、不保证送达。
7. 对。IP 不关心内容，也不保证顺序与送达。
8. 对。反向的 RARP 才是 MAC 解析为 IP。
9. 错。ICMP 封装在 IP 里，属网络层。
10. 对。这正说明“四次”来自全双工两个方向各关一次，不是固定流程。

</details>

### 简答题

<details class="ly-fold">
<summary>9 道简答题</summary>

**1.** 协议与接口有什么区别？

**2.** 写出 OSI 七层的名称与功能。

**3.** 说明 TCP/IP 四层与 OSI 七层的对应关系，并指出两个易错点。

**4.** 什么是对等通信？什么是封装？

**5.** 800 字节应用数据经 TCP/IPv4/以太网发出，帧长多少？首部占多少比例？

**6.** 区分 MTU、MSS、最小帧载荷三个量。

**7.** 叙述三次握手过程，并说明为什么必须是三次。

**8.** 叙述四次挥手过程，并说明为什么是四次。

**9.** 从连接、可靠性、机制、适用场景四方面比较 TCP 与 UDP。

---

**答案要点**

**1.** 协议约束对等层之间的通信规则（语法、语义、时序）；接口只描述相邻上下层之间如何调用服务。前者是“我和对方怎么说话”，后者是“我这一层怎么用下一层”。

**2.** 应用层：提供应用程序间通信；表示层：处理数据格式、数据加密；会话层：建立、维护和管理会话；传输层：建立主机端到端连接；网络层：寻址和路由选择；数据链路层：介质访问与链路管理；物理层：比特流传输。

**3.** 应用层对应 OSI 的 5、6、7 层；传输层对应 4 层；网络层对应 3 层；链路层对应 1、2 层。两个易错点：合并而非删减（表示层、会话层的功能仍在应用层）；“链路层”这个名字通常已包含物理层。

**4.** 对等通信：每一层利用下一层提供的服务，与对方的同一层通信，每层使用自己的协议。封装：每层把上层交来的数据整体当作数据，加上本层首部后交给下一层；七层的每一层都封装。

**5.** 800 + 20 + 20 + 14 + 4 = **858 字节**；首部 58 字节，占 58 / 858 ≈ **6.8%**。

**6.** MTU 1500 是以太网帧载荷上限，也就是 IP 数据报上限；MSS 1460 是 TCP 载荷上限（1500 − 20 − 20）；最小载荷 46 是帧载荷下限（帧长不少于 64），不足补零。

**7.** ① 客户端发 SYN，seq = x；② 服务器回 SYN + ACK，seq = y、ack = x + 1；③ 客户端回 ACK，ack = y + 1。必须三次：两次时服务器无法确认客户端收到了自己的 SYN，一个延迟的旧 SYN 就会让它单方建立连接、空占资源；第三次 ACK 让双方都确认对方收发正常。

**8.** ① 主动方发 FIN；② 被动方回 ACK；③ 被动方数据发完后再发 FIN；④ 主动方回 ACK。四次的原因：TCP 是全双工，两个方向各关一次；被动方收到 FIN 只代表对方不再发数据，自己可能还有数据，所以先确认、后关闭。无数据可发时可合并为三次。

**9.** 连接：TCP 面向连接，UDP 无连接。可靠性：TCP 可靠，UDP 不保证送达。机制：TCP 用序号与确认实现可靠、窗口实现流控、支持全双工；UDP 无这些机制。适用：TCP 用于要求响应的应用（HTTP、FTP、SMTP），UDP 用于一次传小量数据、可靠性交给上层（DNS、TFTP、SNMP）。

</details>
