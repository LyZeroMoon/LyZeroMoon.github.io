【网络协议安全】（十三）VLAN 攻击

VLAN 攻击

标签： #网络协议安全 #VLAN跳跃 #双标签 #DTP #VTP #NativeVLAN

对应第 2 章下册 P58–64。只列考点。

一、双标签跳跃

利用的前提：交换机对 Native VLAN 的帧不加标签（出厂默认 Native VLAN 就是 VLAN 1，而接入口默认也在 VLAN 1）。

攻击原理（两步）：

  1. 攻击者构造含双层 802.1Q 标签的帧，外层标签填 Trunk 链路的 Native VLAN 号（默认 VLAN 1），内层标签填目标 VLAN 号；
  2. 帧进入交换机后，按外层标签被划分到 VLAN 1 转发；到 Trunk 端口发送时，因为 VLAN 号等于 Native VLAN，交换机剥掉外层标签——但内层标签仍在；
  3. 报文以"不带外层标签"的形式上了 Trunk 链路，对端交换机把它当普通帧接收，再按内层标签转发到目标 VLAN。

一句话：交换机只剥一层，攻击者就套两层。剥掉的是攻击者想让它剥的那一层。

三条局限（PPT 明确列出，常考）：

局限 说明
部分交换机丢弃带标签的接入口帧 有的交换机从 Access 接口收到带标签的帧就认为是非法帧，直接丢弃，攻击无法发出
只能单向 攻击者能把包送进 VLAN 2，但回包无法回来
只能发广播/组播 因为是单向，攻击者拿不到被攻击者的 MAC，只能构造二层广播或组播帧

防范：把交换机之间 Trunk 链路的 native VLAN 设置为一个不存在的 VLAN。这样所有帧都必须重新封装、都带标签，攻击者构造的双标签就没有"免标签"通道可用。

二、DTP 跳跃

DTP = Dynamic Trunk Protocol，动态干道协议。管理员可以手工指定链路是否为 Trunk，也可以让交换机自动协商，同时还能协商 Trunk 的封装类型。

漏洞来源：厂家为了方便用户，默认把接口设为主动或被动协商模式——这意味着只要有设备主动向接口发起协商，接口就会形成 Trunk。

攻击步骤：

  1. 攻击者向交换机接口主动发送 DTP 协商包；
  2. 攻击者与交换机之间的链路被协商成 Trunk 链路；
  3. 这条链路可双向传输任何 VLAN 的数据；
  4. 攻击者收发带任意 VLAN 标签的数据，实现对任意 VLAN 的访问。

特点（与双标签正好互补）：

  • 能实现攻击者与被攻击者之间的双向访问；
  • 因此可以绕过防火墙直接访问目标主机。

防范两条：

措施 作用
关闭不需要开启的交换机接口 攻击者根本接不进来
关闭 DTP 接口不再协商 Trunk，攻击者拿不到干道

与双标签的对比（必考辨析）：

双标签跳跃 DTP 跳跃
利用的东西 Native VLAN 不剥内层标签 Trunk 端口自动协商
方向 单向 双向
能发什么 只能广播/组播 任意单播
前提 知道 Native VLAN 号 端口开着 DTP
防范 native VLAN 设为不存在的 VLAN 关闭 DTP、关闭闲置端口

三、VTP 攻击

VTP = VLAN Trunk Protocol，思科私有协议，作用是减少繁重的配置工作：管理员在网络中设一个或多个 VTP Server，在 Server 上创建、删除、修改 VLAN，VTP 会把这些变化通告给其它交换机，实现管理自动化。

三个机制要点：

要点 内容
传输载体 通告只能在 Trunk 链路上传输（所以交换机之间的 Trunk 必须先配好）
通告形式 以组播帧发送
冲突裁决 通告里有 Revision（修订号） 字段，每次增删改递增；收到更高的 Revision 就更新自己；收到更低的，用自己的信息反向覆盖对方

攻击思路（一句话）：发送一个 Revision 极高的 VTP 通告，就能覆盖全网 VLAN 信息。如果把网络里全部 VLAN 都删掉，整个网络的通信随即中断——这是一种破坏型攻击，不是窃听型。

Revision 规则是它的软肋：只比大小，不比新旧，也不认证来源。

三条防范：

措施 原理
关闭不需要开启的交换机接口 攻击者交换机无法接入
与用户计算机连接的接口明确配置为 Access 只要 Trunk 协商不成功，VTP 就无法工作
配置 VTP 密码 攻击者的 VTP 消息被拒绝接收，这是防止攻击的根本措施

四、易错辨析

错误说法 判据 反例
"双标签攻击能双向通信" 只能单向 回包没有外层标签通道，回不到攻击者
"双标签能直接连到目标主机 TCP 端口" 拿不到目标 MAC 只能发广播/组播，通常是泛洪或欺骗
"把 Native VLAN 改成 VLAN 2 就安全了" 换成哪个都存在通道 要设成不存在的 VLAN，强制所有帧带标签
"关闭 Trunk 就能防 DTP" DTP 是协商过程 端口开着主动/被动模式，攻击者一发协商就成 Trunk，要关 DTP
"VTP 是通用标准" 思科私有 非思科设备不支持
"VTP 收到更低的 Revision 会忽略" 会反向覆盖 用自己更高的信息覆盖对方
"VTP 攻击是窃听" 是破坏 删光 VLAN 让全网断通
"VTP 密码只是提醒作用" 是认证 密码不匹配的 VTP 消息被拒收

简答题

9 道简答题

1. 叙述双标签跳跃的完整原理。

2. 双标签跳跃有哪三条局限？

3. 如何防范双标签跳跃？为什么设成"不存在的 VLAN"才有效？

4. DTP 跳跃为什么能成功？

5. DTP 跳跃有什么特点？如何防范？

6. 比较双标签跳跃与 DTP 跳跃。

7. VTP 的作用与工作机制是什么？

8. VTP 攻击的思路是什么？会造成什么后果？

9. 如何防范 VTP 攻击？哪一条是根本措施？

答案要点

1. 攻击者构造带双层 802.1Q 标签的帧，外层填 Trunk 的 Native VLAN 号、内层填目标 VLAN 号，从接入口送入。交换机按外层标签把它划入 VLAN 1 转发，到 Trunk 端口发送时因等于 Native VLAN 而剥掉外层标签；内层标签保留，帧以无标签形式上干道，对端交换机接收后按内层标签把它转发到目标 VLAN。本质是交换机只剥一层，攻击者套两层。

2. ① 有的交换机对接入口收到的带标签帧直接判为非法并丢弃，攻击无法发出；② 只能单向，攻击者能把包送进目标 VLAN，回包回不来；③ 因为单向、拿不到被攻击者 MAC，攻击包只能是二层广播或组播帧。

3. 把交换机之间 Trunk 链路的 native VLAN 设置成一个不存在的 VLAN。原因是：双标签依赖"Native VLAN 帧不打标签"这条通道，只要 native VLAN 与实际 VLAN 都不存在，任何帧经过 Trunk 都必须打标签并被重新封装，攻击者的外层标签就不再享有免标签待遇，内层标签也无法存活。

4. 因为 DTP 默认开启且接口常处于主动或被动协商模式。厂家为了方便，只要有设备主动发起协商，接口就会形成 Trunk。攻击者正是冒充"另一台交换机"发 DTP 协商包，把接入口变成干道，从而获得收发任意 VLAN 标签帧的能力。

5. 特点：攻击者与被攻击者之间可双向访问，能绕过防火墙直接访问目标主机。防范：关闭不需要开启的交换机接口，让攻击者无法接入；关闭 DTP，使接口不再协商 Trunk。

6. 双标签利用 Native VLAN 不剥离内层标签的特性，只能单向、只能发广播或组播，防范靠把 native VLAN 设为不存在的 VLAN；DTP 利用 Trunk 自动协商，能双向、能发任意单播，防范靠关闭 DTP 与闲置端口。前者是"标签技巧"，后者是"协议协商被骗"。

7. VTP 是思科私有的 VLAN 管理协议，用于减少配置工作。管理员设置 VTP Server，在 Server 上增删改 VLAN，VTP 把这些变化以组播通告的形式沿 Trunk 链路传播到其它交换机，其它交换机据此同步 VLAN 数据库。通告带 Revision 修订号，每次修改递增；收到更高 Revision 就更新，收到更低则用自身信息反向覆盖。

8. 攻击者向网络注入一个 Revision 极高的 VTP 通告，因为交换机只比较 Revision 大小、不校验来源，全网都会接受并覆盖自己的 VLAN 信息。如果通告中删除了全部 VLAN，各交换机上的 VLAN 配置被清空，端口所属 VLAN 不存在，整个网络通信中断。

9. 三条：关闭不需要开启的交换机接口；把与用户计算机连接的接口明确配置为 Access 模式，使 Trunk 无法协商成功、VTP 无从工作；配置 VTP 密码，使攻击者发来的 VTP 消息被拒绝接收。其中配置 VTP 密码是根本措施，因为它直接解决了"只比 Revision、不认证来源"这个软肋。

一句话总结：三种 VLAN 攻击各打一个点——双标签打 Native VLAN 不打标签（单向、只能广播）、DTP 打自动协商（双向、可绕防火墙）、VTP 打 Revision 只比大小（破坏型、删光 VLAN 断网）；防范分别对应"设不存在的 native VLAN"、"关 DTP 关闲置口"、"配 VTP 密码"。
